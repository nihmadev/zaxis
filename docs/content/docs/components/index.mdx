Import components from `zaxis` or `zaxis::components`. `zaxis::widgets` remains a
compatibility re-export of the component module.

| [Grid](./grid.mdx) | `ui.grid(id, columns, build)` | Shared column widths and arbitrary cell layouts |

Builders are consumed when shown or added. Use `ui.add(Component::new(...).builder(...))`
for options unavailable in the short form. `Window`, `ScrollArea`, `Grid` and `Table` are containers with `show`, not
implementations of `Widget`.

```rust
use zaxis::{Button, Slider};

ui.add(Button::new("Run").enabled(can_run).tooltip("Run the selected task"));
ui.add(Slider::new(&mut gain, 0.0..=1.0).step(0.05).width(240.0));
ui.add(Slider::new(&mut volume, 0..=100).suffix("%")); // integers: step 1, no decimals
ui.heading("Output");
```

## One rule for enabled and disabled

* **One control:** `.enabled(bool)` on its builder, the same on every control (`Button`,
  `Checkbox`, `Switch`, `Slider`, `TextEdit`, `NumberInput`, `DragValue`, `ComboBox`,
  `ColorPicker`, headers, trees, drag sources and targets).
* **A group:** `ui.add_enabled_ui(bool, build)`.

The deprecated spellings `disabled(bool)`, `Ui::add_enabled`, `button_enabled`,
`checkbox_enabled`, `switch_enabled` and `slider_enabled` still work and mean exactly
the replacements above. The other shared builder names are the same everywhere too:
`id_source(impl Hash)`, `width(f32)`, `style(..)`, `hover_style(HoverStyle)`,
`corner_radius(impl Into<CornerRadius>)` (the old `rounding` is a deprecated alias) and
`status(SemanticStatus)`. Out-of-range arguments are normalized, never panics; see
[Diagnostics](../diagnostics.mdx#value-normalization).

For dependent controls, keep short forms inside an enabled group:

```rust
ui.add_enabled_ui(notifications, |ui| {
    ui.checkbox(&mut sound, "Play sound");
    ui.add(Slider::new(&mut volume, 0..=100).text("Volume").suffix("%").enabled(sound));
});
ui.tab_bar(&mut section, [(0, "General"), (1, "Appearance")]);
ui.selectable_value(&mut accent_blue, true, "Blue");
ui.selectable_value(&mut accent_blue, false, "Green");
ui.muted("Changes are stored in memory.");
```

Enabled state composes with each widget's own `enabled` setting. A nested group
cannot re-enable a disabled parent. Layout and bound values are preserved; disabled
controls cannot activate, focus, or capture the pointer. Custom widgets can query
`Ui::is_enabled()` to follow the same contract.

`selectable` returns activation only; `selectable_value` and `tab_bar` also report
`changed()` when selection changes. Tabs use values as IDs, so values must be unique
within a bar. They use ordinary button Tab/Enter/Space navigation.

Tabs share the row equally. A label wider than its share gets its natural width, and
when the natural widths no longer fit the row, the strip becomes a horizontal
`ScrollArea` (wheel, touchpad, overlay thumb); clicking a tab scrolls it into view.

`Ui::add` returns `Response` and requests follow-up repaint on a click, value change, text submission or text focus loss.
Use `clicked()` for activation and `changed()` for bound-value updates. Exact response
semantics and keyboard controls are in [Input and responses](../input.mdx).

To add a new passive component using the public API, use [Custom components](../development.mdx#custom-components).
