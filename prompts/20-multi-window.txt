Экспорты через модули, корень crate и widgets shim.

Архитектурное решение прими сам после изучения и обоснуй в итоге: либо отдельный Context на окно с общими ресурсами (шрифты, атлас, кэш изображений, тема, лимиты), либо один Context с набором состояний окон. Критерии: ввод, фокус, hover, pointer capture, IME, курсор, popup, tooltip, modal, scroll, drag и viewport строго принадлежат окну; Id уникальны в пределах окна, а retained state не смешивается между окнами с одинаковыми Id; общее тяжёлое состояние не дублируется на каждое окно. Тема, масштаб шрифтов и настройки приложения переключаются для всех окон одним вызовом и применяются в следующем кадре каждого окна. Не вводи глобальных статических переменных и не храни заимствованные closures в Context.

Предоставь короткий API на уровне приложения: идентификатор окна (стабильный WindowKey или аналог, задаваемый приложением, а не индекс), атрибуты окна (заголовок, размер, позиция, min/max size, декорации, resizable, always on top, прозрачность, иконка, начальная видимость, родительское окно), открытие нового окна из update через Frame или Context без прямого доступа к ActiveEventLoop, закрытие конкретного окна, запрос фокуса, смена заголовка и размера, получение размера, scale factor и состояния (focused, minimized, maximized, fullscreen, occluded). Обновление UI оформи как явный вызов per window: App получает окно, для которого строится кадр (например update(&mut self, ctx, frame) с frame.window_key(), либо отдельный метод ui_for_window с дефолтной реализацией, сохраняющей старый однооконный сценарий), и приложение рисует содержимое каждого окна только своими данными. Окно создаётся декларативно либо императивно по выбору приложения, но одно действие даёт одно окно: повторный запрос того же ключа не создаёт дубликат и не пересоздаёт surface. Если приложение перестало запрашивать декларативное окно, оно закрывается без утечки surface, renderer-состояния и retained state.

Жизненный цикл: у каждого окна своя поверхность, swapchain, размер, DPI, режим презентации и очередь перерисовки; resize, смена scale factor, перенос между мониторами с разным DPI, minimize, occlusion и восстановление работают независимо. Закрытие по запросу ОС теперь передаётся приложению как событие CloseRequested для конкретного окна: приложение может подтвердить, отклонить (например через Modal «сохранить изменения?») или закрыть окно; поведение по умолчанию описано явно (закрытие главного окна завершает приложение, закрытие вторичного закрывает только его) и настраивается в RunOptions. Определи главное окно и политику завершения: при закрытии главного окна закрываются дочерние либо приложение живёт, пока открыто хотя бы одно окно; одно действие пользователя даёт одно событие закрытия, повторное закрытие уже закрытого окна безопасно. Окно с родителем закрывается вместе с ним и не уходит за него по Z-порядку там, где ОС это поддерживает. Потеря GPU device восстанавливает все окна, а не только первое; ошибка создания одного окна возвращается приложению как результат и не обрушивает остальные.

Ввод и фокус: события клавиатуры, мыши, колеса, touch, IME и drag попадают только в окно, которому адресованы; потеря и получение фокуса окном корректно сбрасывают pointer capture, нажатые кнопки, активный текстовый ввод и hover, а IME-курсор и composition не утекают в другое окно. Курсор мыши, tooltip и popup принадлежат своему окну и клипируются его границами; модальное окно блокирует только свой Context и не мешает остальным окнам, если приложение явно не блокирует их само. Документируй правило явно. Шорткаты определи как оконные по умолчанию, глобальные на уровне приложения только через явный API. Не реализуй в этой задаче перетаскивание payload между окнами, системный drag-and-drop файлов, нативные меню ОС, несколько мониторов с управлением раскладкой, tray, сохранение и восстановление геометрии окон в файл, headless-окна, embedding в чужие окна и ручное управление Z-порядком: явно перечисли это в документации и limitations.mdx, обнови там строки про Window и native multiwindow.

Рендер и ресурсы: общий device и queue, общие pipelines и атласы; у окна свои surface, uniform-буферы, глубина и промежуточные цели blur, которые освобождаются при закрытии. Кадры окон не блокируют друг друга: перерисовка окна, у которого ничего не изменилось, не происходит, а окна в покое не будят цикл. Repaint scheduling считает ближайший дедлайн по всем окнам и возвращает ControlFlow без busy loop; анимация в одном окне не вызывает перерисовку остальных. Невидимые, свёрнутые и закрытые окна не рендерятся и не запрашивают кадры. Загрузка изображений и шрифтов доступна всем окнам: изображение, загруженное в одном окне, не загружается повторно в другом. Диагностика и debug overlay показывают данные текущего окна и счётчики по всем окнам; существующие метрики не ломаются.

Оформление нативного chrome: TitleBar, native_chrome.rs и RunOptions.rounded_corners работают для каждого окна отдельно; вторичные окна могут иметь системные декорации или кастомный TitleBar, перемещение и кнопки окна адресуются нужному окну, а не первому.
