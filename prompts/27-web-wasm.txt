Время. Заведи один внутренний модуль (например src/time.rs, pub(crate)), который под cfg(not(target_arch = "wasm32")) реэкспортирует std::time::Instant и Duration, а под wasm32 берёт их из крейта web-time (зависимость только для wasm32 через [target.'cfg(target_arch = "wasm32")'.dependencies]). Замени все `std::time::Instant` в crate на этот алиас одной механической правкой, без изменения логики; публичные сигнатуры, где Instant торчит наружу (например run_at, needs_repaint_at, дедлайны), должны остаться совместимыми на native, а на web использовать тот же алиасный тип. Если окажется, что публичный Instant ломает API, зафиксируй решение и обоснуй его в итоге. Больше нигде в коде не должно остаться прямого std::time::Instant (проверь rg).

Раннер. Раздели runner на платформы: общую часть (диспетчеризация событий winit в Context, repaint scheduling, окна, RunOptions) оставь платформонезависимой, а платформенное вынеси в runner/native.rs (как сейчас: pollster::block_on, ControlFlow::WaitUntil, несколько окон, native chrome, retry при потере device) и новый runner/web.rs. Web-раннер: создаёт canvas (по id из RunOptions или создаёт сам и добавляет в body), создаёт Renderer асинхронно через wasm_bindgen_futures::spawn_local и EventLoopProxy (событие «renderer ready», после которого строится первое окно и кадр), без block_on; сначала пробует wgpu::Backends::BROWSER_WEBGPU, затем GL (WebGL2) с честными downlevel-лимитами; resize canvas и device pixel ratio берёт из winit (ResizeObserver/scale factor), canvas занимает указанный контейнер или всё окно браузера; repaint scheduling переводится на ControlFlow::Wait/WaitUntil winit web (без busy loop, фоновая вкладка не крутит кадры); паника выводит сообщение в console (console_error_panic_hook, под фичей или только в web-раннере). Multi-window на web: одно окно-canvas, повторный запрос второго ключа возвращается приложению ошибкой/результатом, а не паникой; задокументируй. Публичный API run и run_with_options остаётся одним для обеих платформ: на web run_with_options возвращается сразу после регистрации цикла (winit spawn_app), это явно описано в доках. Не дублируй App, Frame и Context-логику между раннерами.

Платформенные зависимости и фичи. Вынеси под cfg(not(wasm32)): arboard, pollster, нативные пути загрузки; под cfg(wasm32): web-sys (Clipboard, Window, Document, HtmlCanvasElement, нужные события), wasm-bindgen, wasm-bindgen-futures, web-time, js-sys. Подбери фичи web-sys минимально. Буфер обмена на web: копирование через navigator.clipboard.writeText из обработчика пользовательского жеста и событий copy/paste документа; вставка получает текст из paste-события, а не из синхронного чтения; Ctrl+A/C/V в TextEdit и SelectableLabel работают через эти пути, ошибки разрешений не паникуют и репортятся тем же report_clipboard. Изображения: на wasm нет std::thread (без COOP/COEP) и std::fs, поэтому worker декодирует синхронно по кадрам или порциями (с лимитом времени кадра) под cfg, загрузка по пути отключена, остаются байты и URL через fetch (если это просто, иначе только байты — реши сам и зафиксируй). Шрифты: системные шрифты недоступны, на web используются только bundled-* и явно загруженные; если cosmic-text пытается сканировать систему, отключи это под cfg(wasm32). Курсоры, IME и ввод: проверь, что winit web корректно передаёт Ime, wheel, touch, pointer capture, key events (Tab/стрелки не уходят браузеру: preventDefault там, где виджет их потребил), контекстное меню браузера подавляется над canvas. Native chrome и RunOptions.rounded_corners на web — no-op с документированным поведением; TitleBar рисуется как обычный виджет или скрывается.

Рендер. Проверь, что все WGSL-шейдеры и pipelines проходят валидацию на WebGPU и в WebGL2 (naga → GLSL ES): без неподдерживаемых features, storage buffers и push constants; лимиты запрашивай через adapter.limits()/downlevel_webgl2_defaults с фолбэком, размер текстуры и атласа учитывай по max_texture_dimension_2d; blur и промежуточные цели работают или аккуратно деградируют (без blur, но без падения) на WebGL2; формат surface выбирается из поддерживаемых браузером (preferred canvas format, sRGB handling), alpha mode для прозрачного фона берётся из capabilities. Потеря device/контекста WebGL восстанавливается тем же путём, что и на native, либо документирована как ограничение.
