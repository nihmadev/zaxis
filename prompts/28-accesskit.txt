Что нужно знать про AccessKit (проверь по docs.rs и исходникам реально резолвнувшихся версий, а не по этому тексту; я свериться мог только частично). Актуальные версии на 2026-10: accesskit 0.25.1, accesskit_winit 0.34.1 (MSRV 1.87, зависит от winit ^0.30.5 — совместим с нашим winit 0.30.13; тянет accesskit_windows/macos/ios, опционально accesskit_unix через фичу `accesskit_unix` и `tokio`, а также rwh_05/rwh_06). В ~/.cargo/registry лежат СТАРЫЕ accesskit 0.24.1, accesskit_winit 0.32.2, accesskit_consumer 0.35.0, accesskit_windows 0.32.1 — используй их максимум для ориентировки, сверяй API с cargo doc после добавления зависимости. Модель: платформенный адаптер держит дерево узлов Node с NodeId (newtype над u64) и Role; приложение шлёт TreeUpdate { nodes: Vec<(NodeId, Node)>, tree: Option<Tree> (обязательно в первом апдейте), tree_id/focus }; узел заменяется целиком (неизменные поля надо передавать снова), добавление/удаление ребёнка требует апдейта родителя с изменённым children, каждый не-корневой узел обязан быть достижим от корня, иначе паника адаптера. Адаптер winit создаётся ТОЛЬКО для ещё невидимого окна (иначе panic): окно создаётся with_visible(false), затем Adapter::with_event_loop_proxy / with_direct_handlers / with_mixed_handlers, затем show; process_event(&window, &winit_event) вызывается для КАЖДОГО WindowEvent до собственной обработки; update_if_active(|| TreeUpdate) вызывает замыкание только если AT реально подключён (ленивая активация), и при инициализации через proxy обновление обязано содержать полное дерево. События от AT приходят как accesskit_winit::Event{window_id, window_event: InitialTreeRequested | ActionRequested(ActionRequest) | AccessibilityDeactivated} — на Windows/AT-SPI из других потоков, поэтому через EventLoopProxy и вариант в нашем UserEvent (T: From<Event> + Send). ActionRequest { action, target_tree, target_node, data: Option<ActionData> }; Action: Click, Focus, Blur, Collapse, Expand, Increment, Decrement, SetValue (ActionData::Value|NumericValue), ReplaceSelectedText, SetTextSelection (TextSelection{anchor, focus} из TextPosition{node: TextRun, character_index}), ScrollDown/Up/Left/Right (ScrollUnit), ScrollIntoView (ScrollHint), ScrollToPoint, SetScrollOffset, ShowContextMenu, ShowTooltip/HideTooltip, CustomAction и т.д. Текстовая модель у AccessKit жёсткая: поле ввода — узел с ролью TextInput/MultilineTextInput и value, а содержимое — дочерние узлы Role::TextRun, по одному на визуальную строку, с character_lengths (длины кластеров в байтах UTF-8), word_lengths, character_positions/character_widths в системе координат строки, bounds каждой строки и text_direction; выделение и каретка выражаются TextSelection поверх TextRun-узлов. Координаты bounds — в координатах окна (физические пиксели клиентской области, как их ждёт адаптер; учти scale factor и локальные transform/clip zaxis), у прокручиваемых контейнеров ставь clips_children и scroll_x/y(+min/max). Выясни по исходникам адаптеров, что именно обязательно для Windows UIA (имена, ControlType, Invoke/Toggle/Value/RangeValue/ExpandCollapse/Scroll/Selection/Text patterns через роли и свойства) и что для macOS/AT-SPI.

Архитектура, которую нужно реализовать (выбирай проще, но без заглушек). 1) Семантический слой в Context: за проход собирается лёгкий список A11yNode (stable Id → NodeId, родитель, роль, имя/label, описание, value/numeric value/min/max/step, toggled, selected, expanded, disabled, hidden, orientation, level/position_in_set/size_of_set, supported actions, bounds в координатах окна, clip, ссылка на фокусируемость) через обычный стек Ui-скоупов: родитель определяется структурой вызовов Ui (horizontal/vertical/scopes/Window/Card/Popup/Modal), а не отдельным API на каждый виджет. Виджеты описывают себя минимальным вызовом рядом с уже существующей регистрацией hit-региона (например Ui::a11y(...) / внутренний билдер), а для внешнего кода — публичный API: .accessible_label(..), .accessible_description(..), .accessible_role(..), .accessibility_hidden() для декоративных виджетов, и связь Field label ↔ контрол и error/description. Имя по умолчанию берётся из видимого текста виджета (Button — его label, Checkbox — подпись и т.д.); виджеты без текста (иконочные кнопки, Switch без подписи, слайдер) должны требовать или получать осмысленное имя и сообщать о его отсутствии через существующую диагностику (src/context/diagnostics.rs), а не молча отдавать пустую строку. Когда AT не подключён, сбор должен быть почти бесплатным: проверка одного флага в Context без аллокаций (замеряй в benches/performance.rs: idle-сцена с отключённой и с включённой доступностью не должна регрессировать при выключенной). 2) Построение и дифф: в finish_frame после сортировки слоёв и hits строится дерево окна: корень Role::Window, в нём слои (Window-виджеты, popup, modal, tooltip, toast) в порядке z/фокуса; модальный диалог — Role::Dialog с set_modal, остальное под ним скрыто от AT; дерево строго валидно (достижимость, уникальные NodeId; повторяющиеся Id в одном проходе разруливай детерминированно и репорти диагностикой). Хранится предыдущее дерево окна по NodeId; на каждом кадре в TreeUpdate уходят только изменившиеся узлы (Node: PartialEq) и их изменённые родители, удалённые виджеты — апдейтом родителя; полное дерево только по InitialTreeRequested. NodeId выводится из Id::value() со стабильными дочерними id для текстовых строк и виртуальных элементов, корень и служебные узлы резервируются так, чтобы не пересекаться с пользовательскими Id. Не запрашивай redraw «для AT» бесконечно: перерисовка только по реальным изменениям. 3) Фокус: TreeUpdate.focus всегда равен фокусируемому узлу из focused_widget (или корню окна/диалога, если фокуса нет); смена фокуса клавиатурой, мышью, request_focus и Action::Focus даёт ровно одно обновление; Tab-цикл и порядок обхода AT совпадают с порядком дерева; фокус-ловушка Modal учитывается. 4) Действия обратно: ActionRequest от AT попадает в UserEvent, затем в Context как синтетический ввод ровно одного пользовательского действия (Click → то же состояние clicked, что и у настоящего клика, включая Hyperlink с LinkActivation, Checkbox/Switch toggle, RadioGroup/SegmentedControl/Tab выбор, ComboBox/ListBox/Tree/MenuBar пункты, CollapsingHeader/Tree Expand/Collapse; Increment/Decrement и SetValue для Slider/DragValue/NumberInput с теми же clamp/step/округлением и changed-событием, что у мыши и клавиатуры; SetValue/ReplaceSelectedText/SetTextSelection для TextEdit через EditBuffer и историю undo, а не в обход; ScrollDown/Up/ScrollIntoView/SetScrollOffset для ScrollArea, ListBox, Table, Tree, включая прокрутку к строке, которая сейчас не построена виртуализацией; ShowContextMenu, ShowTooltip). Действие над несуществующим, скрытым или disabled узлом игнорируется без паники; одно действие — одно событие и один redraw; результат виден в следующем проходе, как у обычного ввода. 5) Раннер: вынеси работу с адаптером в src/accessibility/adapter.rs; на native окно создаётся скрытым, адаптер создаётся до первого показа (учти существующие WindowOptions::with_visible, Windows::set_visible, прозрачные окна, native chrome, recreation окна и retry/потерю device — адаптер живёт пока живёт окно, а не рендерер), process_event вызывается из Runner::dispatch до Context::on_window_event, update_if_active — в redraw после построения кадра; несколько окон — по адаптеру и дереву на окно, закрытие окна освобождает адаптер; AccessibilityDeactivated сбрасывает кэш предыдущего дерева и выключает сбор. Платформенные нюансы: Windows — UIA и ленивая активация при подключении Narrator/NVDA; macOS — адаптер в winit-слое; Linux — только за фичей accesskit_unix (D-Bus, tokio/async-io; не ломай сборку без неё и без Wayland/X11 сессии). Первый InitialTreeRequested через proxy значит плейсхолдер-дерево до следующего кадра: форсируй redraw и отдай полное дерево сразу; если можно вернуть дерево синхронно (with_mixed_handlers + разделяемый снимок), оцени и выбери осознанно. 6) wasm32: accesskit_winit не поддерживает web — под cfg(target_arch = "wasm32") слой должен компилироваться (cargo check --target wasm32-unknown-unknown --lib не ломается), сбор и адаптер отключены, это явно описано в limitations и web.mdx; не изображай веб-поддержку.

Тексты и вводы (самая тонкая часть, делай честно). TextEdit single и multiline: роль TextInput / MultilineTextInput, value = полный текст (для password — без значения, role/protected), placeholder, read_only, disabled, caret и выделение как TextSelection по TextRun-узлам, TextRun на каждую визуальную строку Doc (после переноса) с character_lengths по кластерам графем (согласовано с edit_buffer и text_geometry, не по char и не по байтам), word_lengths по Unicode-границам слов, character_positions и character_widths из реальной геометрии глифов (одни и те же позиции для hit-testing, paint и дерева), bounds строки с учётом scroll и clip; IME-композиция не должна ломать дерево. SelectableLabel, Hyperlink, rich_label, Label: Role::Label / Paragraph с TextRun, ссылки внутри rich-текста — отдельные узлы Role::Link с именем, url и возможностью Click, выделение статического текста отражается как text_selection; ellipsis-текст отдаёт полный исходный текст. Большие тексты не пересобирают строки каждый кадр — кэшируй модель строк вместе с layout и ограничивай размер (для дерева можно отдавать только видимые и соседние строки, но корректно и документированно). Пустой текст, эмодзи, комбинируемые символы, RTL, NaN и нулевая ширина не паникуют и не дают невалидный TextPosition.

Пользовательские и сторонние виджеты: Ui::interact и Widget для кастомных виджетов получают явный способ описать узел (роль, имя, значение, действия, обработчик действия), документируй в docs/content/docs/custom-widgets.mdx; кастомный виджет без описания не попадает в дерево как мусор — он либо не виден AT, либо виден как безымянная группа с диагностикой.

Динамика и анимации: дерево строится из состояния виджетов, а не из анимированных значений (Rect во время анимации не должен спамить апдейтами каждый кадр: дебаунс по изменению семантики и bounds с допуском); reduced_motion и prefers-reduced-motion не влияют на дерево; settled-состояние не запрашивает redraw; скрытые и невидимые за clip/ScrollArea виджеты помечаются offscreen/clipped корректно, а закрытые popup/tooltip/menu исчезают из дерева в тот же проход.

Публичный API и фичи. Фича `accesskit` в Cargo.toml (реши осознанно, включена ли по умолчанию: «настоящая поддержка» предполагает default-on с ленивой активацией и нулевой стоимостью без AT, но проверь вес зависимостей windows/zbus и обоснуй), `cargo check --lib --no-default-features --locked` и MSRV 1.90 должны проходить, accesskit_unix — отдельная под-фича. Реэкспортируй в lib.rs только нужное (A11yRole-обёртки или прямой accesskit::Role — реши и обоснуй; предпочитай собственные тонкие enum'ы, чтобы мажорные версии accesskit не ломали публичный API; accesskit в публичной сигнатуре допустим только там, где иначе нельзя, и это нужно зафиксировать). Опция в RunOptions/WindowOptions для выключения интеграции. Тестовый хук в zaxis::testing: получить текущее дерево доступности, найти узел по роли/имени, послать ActionRequest и проверить результат без winit, без GPU и без реального AT.
